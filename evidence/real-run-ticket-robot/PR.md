# Gantry releases parts at 450 mm instead of converting BIN_X_MM (540 mm) to pixels

## Summary
Fixes a unit-conversion bug in the Cell 3 gantry pick-and-place controller where the gantry stopped at `x = 450 mm` and dropped every part onto the floor in front of the bin instead of placing them inside the bin at `540 mm`.

## Root Cause
In `app/public/robot/controller.js`, the `TO_BIN` state called `io.moveTo(CELL.BIN_X_MM, mm(CELL.CARRY_Y_MM))`, passing the raw millimetre constant `CELL.BIN_X_MM` (`540`) instead of converting it to pixels via `mm(CELL.BIN_X_MM)`. Because `io.moveTo` expects pixel coordinates (`PX_PER_MM = 1.2`), commanding `540 px` moved the gantry to `540 / 1.2 = 450 mm` rather than `540 mm` (`648 px`).

## Fix
- Wrapped `CELL.BIN_X_MM` in `mm(...)` inside the `TO_BIN` case of `createController()` in `app/public/robot/controller.js` (`io.moveTo(mm(CELL.BIN_X_MM), mm(CELL.CARRY_Y_MM))`).

## Verification
- Ran the automated pick-and-place simulation test against the fixed build and confirmed via screen recording that the gantry carries all three parts to the bin at `540 mm`, stacking all 3 parts inside the bin and finishing with `In bin: 3 / 3`, `Dropped: 0`, and `Status: Done`.
