# Toggling a todo's done state does not persist across page reloads

## Context
When users checked or unchecked a todo item in Taskly, the UI updated optimistically, but refreshing the page caused all todos to revert to their initial unchecked state.

## Root Cause
In `app/server.js`, the `PATCH /api/todos/:id` route handler compared `t.id === req.params.id` using strict equality. Because `t.id` is a number and `req.params.id` is a string, the lookup always failed and returned a `404 Not Found` without persisting the `done` state on the server.

## Fix
Convert `req.params.id` to a number (`const id = Number(req.params.id)`) before searching the `todos` array in `PATCH /api/todos/:id`, matching the behavior in the `DELETE` handler.

## Verification
Verified via automated browser test recording: added 'Buy milk', 'Walk dog', and 'Pay rent', toggled 'Buy milk' and 'Pay rent' to done, reloaded the page, and confirmed that both items remained checked and struck through after reload.
